# 降低专有名词 Issue 误报率 — 实施计划

## 问题分析

### 现状

`validators.py:279-302` 中的专有名词提取与验证逻辑存在系统性误报问题。验收报告（v0.1.13）显示：30 个 answer_evidence_issues 中有 **18 个（60%）是专有名词误报**，直接导致 `ground_truth_confidence` 和 `issues 总数` 两项指标未达标。

### 根因

正则 `[\d\u4e00-\u9fff]{2,8}(?:股份|集团|公司|行业|市场|技术|产品|业务)` 会匹配**任何** 2-8 字符 + 后缀的片段，无法区分"真专有名词"与"LLM 推理性过渡语"。

### 误报模式分类（从 golden testset 实际数据归纳）

| 模式 | 典型误报 | 数量占比 |
|------|---------|---------|
| 指示代词 + 后缀 | 这些技术、这些产品、该产品、其业务 | ~15% |
| 动词短语 + 后缀 | 导致全行业、推动市场、说明行业、仅靠技术 | ~30% |
| 判断/推理语 + 后缀 | 这表明行业、意味着市场、标志着行业 | ~20% |
| 时间限定 + 后缀 | 2024年银行业务、本周传媒行业、年光伏行业 | ~15% |
| 连词/转折 + 后缀 | 但洋河股份、而新发产品、且不断升级技术 | ~10% |
| 量词/修饰 + 后缀 | 多项行业、各种技术、高效化的产品 | ~10% |

### 已有缓解措施及其局限

1. **三级渐进匹配**（已实现）：精确 → 去数字前缀 → 去后缀核心词匹配。解决了"电子行业→电子"的改写匹配问题，但**不解决提取阶段的误报**。
2. **对抗性题过滤**（已实现）：`filter_adversarial_issues` 对 adversarial 类型跳过所有专有名词 issue。仅覆盖 1 种问题类型。

---

## 解决方案

### 核心思路：提取后过滤（Post-Extraction Filtering）

保持现有正则不变（它负责"召回"），在提取后增加一个 `_is_genuine_proper_noun()` 过滤函数，识别并排除推理性过渡语。

### 为什么不直接改正则？

中文没有空格分词，纯正则无法可靠判断"2-8 字符前缀"是否为名词短语。后过滤方式更灵活、可测试、可迭代。

### 过滤规则设计（四层检查）

#### 第一层：前缀起始字符检查

提取匹配项的前缀（去掉后缀后的部分，再去掉开头数字），如果**以**以下字符开头，则排除：

- 指示代词：这、那、此、其、该、本、某
- 连词：而、但、且、或、并、及
- 否定词：没、不、未、非、无
- 介词：从、到、由、为、于、以、对、向、给、比、在、被、把、将、使、让
- 系词/存在动词：是、有

#### 第二层：前缀起始词组检查

如果前缀**以**以下多字符词组开头，则排除：

- 常见动词：导致、推动、说明、表明、代表、仅靠、构成、意味、采用、面临、成为、反映、加剧、引发、退出、超越、支持、倾向、升级、检测、补充、提供、确保、加速、倒逼、促使、混淆、跑赢、标志、使得、属于、基于、源于
- 序数词：一是、二是、三是、首先、其次、再次、最后
- 量词短语：多项、多种、多个、各类、各种、全部、所有

#### 第三层：前缀包含词检查

如果前缀**包含**以下多字符词，则排除：

- 结构助词（作为动词短语组成部分）：不了、着、过 → 实际用单字符检查：的、了、着、过
- 常见动词：同第二层的动词列表
- 连接词：但是、然而、不过、虽然、尽管、因为、所以、因此、因而、从而、进而、反而、相反、同样、同时、此外、另外、而且、并且

#### 第四层：前缀结尾字符检查

如果前缀（去掉开头数字后）**以**以下字符结尾，则排除（时间词后缀表明这是时间限定短语）：

- 月、年、周、天

### 边界情况处理

| 边界情况 | 处理方式 | 理由 |
|---------|---------|------|
| "中国光伏行业" → 前缀"中国光伏" | ✅ 通过 | 无功能词，是合法名词短语 |
| "洋河股份" → 前缀"洋河" | ✅ 通过 | 无功能词，是合法实体名 |
| "封闭式理财产品" → 前缀"封闭式理财" | ✅ 通过 | "式"是构词后缀，不是功能词 |
| "银行理财市场" → 前缀"银行理财" | ✅ 通过 | 无功能词，是合法名词短语 |
| "中国的光伏行业" → 前缀"的光伏" | ❌ 过滤 | "的"是结构助词 |
| "电子行业" → 前缀"电子" | ✅ 通过 | 无功能词 |
| "通信行业" → 前缀"通信" | ✅ 通过 | 无功能词（虽是通用行业名，但在金融研报语境中属于专有名词） |

### 对其他使用专有名词正则的位置的影响

| 文件 | 函数 | 影响 | 是否需要同步修改 |
|------|------|------|----------------|
| `validators.py:279` | `validate_answer_evidence_consistency` | 直接影响验证结果 | **必须修改** |
| `generator.py:569` | `_extract_segment_keywords` | 影响关键词提取质量 | 建议修改（低优先级） |
| `chunk_locator.py:486` | `_extract_key_terms` | 影响术语提取质量 | 建议修改（低优先级） |

## 实施步骤

### Step 1: 定义过滤常量

在 `validators.py` 中定义模块级常量：

```python
_PROPER_NOUN_PREFIX_START_CHARS = set("这那此其该本某而但且或并及没不未非无从到由为于以对向给比在被把将使让是有")
_PROPER_NOUN_PREFIX_START_WORDS = frozenset(["导致", "推动", "说明", "表明", ...])
_PROPER_NOUN_PREFIX_CONTAINS_WORDS = frozenset(["导致", "推动", "说明", ...])
_PROPER_NOUN_PREFIX_CONTAINS_CHARS = set("的了着过")
_PROPER_NOUN_PREFIX_END_CHARS = set("月年周天")
```

### Step 2: 实现 `_is_genuine_proper_noun()` 函数

在 `validators.py` 中新增函数，接收匹配到的名词和原始答案文本，返回布尔值。

### Step 3: 在 `validate_answer_evidence_consistency` 中调用过滤

在 `re.findall` 之后、遍历验证之前，过滤掉非真专有名词。

### Step 4: 编写测试

在 `tests/test_golden_testset.py` 中新增 `TestIsGenuineProperNoun` 测试类，覆盖：
- 每种误报模式都被正确过滤
- 真专有名词不被误过滤
- 边界情况

### Step 5: 运行现有测试 + lint

确保无回归。

### Step 6: （可选）同步修改 generator.py 和 chunk_locator.py

将 `_is_genuine_proper_noun` 提取为公共函数，在其他两处也应用过滤。

## 风险与缓解

| 风险 | 缓解措施 |
|------|---------|
| 过滤规则过严，漏掉真专有名词 | 块列表仅包含明确的功能词/动词，不包含可能出现在名词中的字符（如"中""国"） |
| 新的误报模式未覆盖 | 块列表设计为可扩展的 frozenset，后续可增量添加 |
| "中国的光伏行业"被误过滤 | 实际 LLM 答案极少使用"的"连接专有名词，且即使过滤也不影响核心验证（"光伏行业"仍会被匹配到） |
