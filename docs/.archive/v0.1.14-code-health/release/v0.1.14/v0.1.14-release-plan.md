# Plan: v0.1.14 Release

## 版本定位

### 主题：代码健康治理

### 叙事

> 看得见的产品有了，看不见的骨架也得撑得住。

v0.1.13 让 RAG 有了可展示的界面，但底层四个巨型文件（5000行、3000行、1800行、1500行）已经成了"轻度屎山"的典型症状。这一版把上帝文件拆包为独立模块，补齐了 pipeline 策略模式和 Pydantic 配置校验，同时完成了文档目录的叙事化重组。

### 叙事线延续

| 版本 | 主题 | 一句话 |
|------|------|--------|
| v0.1.9 | 评测双引擎 | 有了可信的尺子 |
| v0.1.10 | 解析新纪元 | 有了自由的源头 |
| v0.1.11 | 链路统一 | 有了统一的基准 |
| v0.1.12 | 项目治理 | 有了可持续的节奏 |
| v0.1.13 | RAG 可视化 | 有了可展示的产品 |
| **v0.1.14** | **代码健康治理** | **有了可维护的骨架** |

## 实施步骤

### Step 1: 更新 CHANGELOG.md

在 `[Unreleased]` 和 `[0.1.13]` 之间插入 `[0.1.14] - 2026-04-29` 条目，按 Added / Changed / Fixed / Refactored 分类记录 73 个 commit 的变更：

**Added:**
- Pipeline 策略模式（query_rewrite_strategies.py + retrieval_strategies.py）
- ExperimentConfig Pydantic 模型（experiment_schemas.py）
- Golden testset 生成质量 5 项改进（自适应 CJK 引文长度、对抗性过滤、证据自动补充、per-type max_tokens、missing-type 专用 prompt）
- Generator per-call max_tokens 覆盖
- Meal 文件列表公司名标签
- create_artifact_cache 工厂函数
- EvaluationSample dataclass
- dev-story.md 开发随笔
- release-cadence.md 版本节奏指南

**Changed:**
- 文档目录重组：docs/guides/ → docs/user-guides/ + docs/dev-guides/
- 归档目录按版本叙事重构
- ExperimentResult → ReportExperimentResult 重命名
- DEFAULT_EVAL_CONFIG 和 get_eval_config 统一到 metrics/utils.py
- README 重写 + 修复根级文档链接
- version-history.md 重构为 5 版本叙事线

**Fixed:**
- is_genuine_proper_noun 过滤器降低假阳性率
- save_manifest 返回类型注解修正
- SummaryConfig 补充缺失字段
- 去除硬编码 API URL 和模型名
- 提取后的测试引用更新

**Refactored:**
- src/test_generator.py（~5000行）→ src/test_generation/ 包（9 子模块）
- src/meal.py（~1500行）→ src/meal/ 包（6 子模块）
- eval/run_experiment.py（~3000行）→ eval/runner/ 包（8 子模块）
- eval/experiment_reporter.py（~1800行）→ eval/reporter/ 包（5 子模块）
- 移除业务模块 __main__ 块
- 移除 chunk_locator.py 废弃函数
- 移除 manager.py 冗余 import
- Ruff 自动格式化
