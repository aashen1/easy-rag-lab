# archive/ 目录的角色

## 这里面有什么？

这里存放着项目从`git init`以来的所有 AI 需求文档、spec 文档、分析文档、修复文档、验收文档等。

它的目的是留档，用于在未来有需要时随时追溯一个开发决策。

已知问题：组织度不足，结构凌乱，未经仔细整理

## 每个文件夹各是什么？

plans 和 specs 分别对应 TRAE IDE 的两种模式：

`/plan`：优先规划任务的执行方向，用户确认后再执行

`/spec`：根据需求细化完整的规范、任务、验收文档，用户确认后再严格执行，适合复杂的长线任务

这两种模式，分别会在`.trae/documents`和`.trae/specs`目录下生成单个（plan）或者三个（spec）文档。

它所在的目录`.trae/`暗含着“内部文件”的意思，AI 的默认行为也不会将其纳入提交。

但考虑到阅读 AI 生成的几千行代码，可能还不如读一篇一两千字的需求文档来得直白，因此本项目还是将其加入了 commit 当中予以追溯，并定期移动到此处进行存档。

这里的文档一般是供 AI 在需要时查找，一般不是为人类读者预备的。
