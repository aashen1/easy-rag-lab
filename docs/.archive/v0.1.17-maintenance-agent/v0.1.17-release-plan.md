# v0.1.17 发版计划

## 一、版本主题

**修得好**（Repair Well）

### 叙事

> v0.1.16 让系统学会了"看病"——Bad Case 从发现到诊断全链路闭环。
>
> 这一版让系统拥有了"自主维修"的能力：LangGraph Agent 编排全链路工具调用，Session 持久化让对话不再丢失，经验积累让维修越做越聪明。共享单元层为 Agent 和实验系统架起统一桥梁，Pydantic 配置校验让系统更健壮，Streamlit 维修工页面让 AI 维修触手可及。
>
> 不是只会诊断，而是能动手修好。

## 三、v0.1.16→HEAD 核心变更摘要

### 3.1 新功能

1. **维修工 Agent 系统**（核心新增）
   - LangGraph StateGraph 编排（agent → approval → tools 三节点循环）
   - 20+ 个 @tool 覆盖全链路操作
   - 审批机制（interrupt + FORBIDDEN\_OPERATIONS 硬拦截）
   - 安全防护（诊断前置守卫、删除计数阈值、.trashbin 自动备份）
   - CLI 入口（`pixi run agent`）+ Streamlit 维修工 Tab
2. **Session 管理系统**
   - SQLite 持久化 Session CRUD
   - session\_id/thread\_id 自动生成
   - 孤儿 checkpoint 迁移
3. **经验持久化系统**
   - InMemoryStore+JSON → SqliteStore 迁移
   - 旧 JSON 数据自动迁移（单向，不可回退）
   - 手动触发经验保存（save\_experience\_tool）
4. **共享单元层**（`src/core/ops/`）
   - parse / chunk / embed / index / evaluate 6 个模块
   - 为 Agent 和实验系统提供统一接口
5. **Pydantic 配置校验**（FEAT-024）
   - config.yaml 的 Pydantic 模型验证
   - 必填项校验 + 范围校验
   - 集成到 load\_config()
6. **维修/对比报告系统**
   - maintenance\_report.py：Markdown 维修报告
   - comparison\_report.py：多方案指标对比
7. **资源管理增强**
   - RAGPipeline.close() 释放重资源
   - Embedder/Reranker/BM25Retriever unload/clear 方法
   - 实验 variant 间共享 Embedder
8. **Web UI 改进**
   - streamlit-searchbox 集成
   - 公司名标签显示
   - 思考过程折叠/展开
   - 对话框位置修正
   - Mermaid 架构图渲染

### 3.2 新增依赖

## 七、v0.2.0 展望

根据 version-history.md 规划，v0.2.0 的核心目标是：

1. RAGAS 深度核实，五大指标全部验收
2. 完善自动化评测系统
3. 标定稳定 baseline
4. dev → main 合并
5. 开源版本库发布

v0.1.17 的共享单元层（src/core/ops/）已完成 Phase C 迁移（实验系统统一到共享单元），parser/chunker/embedder/indexer 均已通过 core/ops 调用，这是 v0.2.0 的前置条件之一。

> **文档系统警示**：本次调查发现 .trae/specs/ 中存在多处过时状态信息（Phase C 标记 0% 实际已完成、C6 标记 50% 实际已 100%），这些过时文档会误导后续 session 的判断。建议在发版前清理或标注这些过时 spec 文档。
