## 三、版本叙事

### 前序叙事链

```
量得准 → 解得开 → 合得拢 → 管得住 → 看得见 → 撑得住 → 跑得快
 v0.1.9   v0.1.10  v0.1.11  v0.1.12  v0.1.13  v0.1.14  v0.1.15
```

### v0.1.16 叙事：**诊得明**

> v0.1.15 让系统跑得快，但跑得快不等于跑得对。
>
> 这一版让系统学会"看病"——Bad Case 从发现到追踪到诊断到根因定位，全链路闭环；解析链路从"能用"升级为"精调"，混合架构让表格不再是盲区；实验系统学会"省着花"，报告复用和缓存校验让算力不再浪费；测试集管线从碎片化走向统一入口。
>
> 不是跑得更快，而是跑得更明白。

### 叙事展开：四个故事线

#### 故事线 1：从"跑得快"到"诊得明"——Bad Case 闭环分析

v0.1.15 让实验跑得快了，但跑完之后呢？发现某个问题回答不好，只能靠人肉翻日志。这一版建立了完整的 Bad Case 闭环：

1. **收集**：Web UI 一键标记 badcase/goodcase，CLI 交互模式 `/badcase` 命令，CLI 单查模式自动入历史环形缓冲区
2. **追踪**：Pipeline trace 捕获（检索了哪些 chunks、用了什么策略、token 消耗），5 文件完整可复现
3. **诊断**：Case Analyzer 页面可视化，Retrieval Analyzer 分析检索质量，Root Cause Diagnoser 自动归因
4. **根因定位**：Chunk Finder 定位问题 chunk，Ground Truth Finder 补充标准答案

**关键文件**：`src/case_collector.py`, `src/trace_models.py`, `src/case_diagnoser.py`, `src/retrieval_analyzer.py`, `src/ground_truth_finder.py`, `src/query_history.py`, `src/interactive_qa.py`, `src/app_pages/case_analyzer.py`

#### 故事线 2：从"能用"到"精调"——混合解析链路

PDF 解析一直是 RAG 的源头。之前只有一种解析器，表格质量是短板。这一版做了两件大事：

1. **两步法架构**：CompositeParser = 主力解析器 + 表格增强器，热插拔组合
2. **精调验证**：6 种候选管线抽样实验 + 独立 parser benchmark 模块，用数据说话

最终确定默认链路为 `pymupdf4llm + pdfplumber(text)`，OCR 关闭。表格补强从单维度（行数）升级为多维度质量比较（行数、空单元格率、合并单元格率），默认优先使用补强结果。

**关键文件**：`src/parsers/composite_parser.py`, `src/parsers/fitz_parser.py`, `src/parsers/pdfplumber_enhancer.py`, `eval/parser_benchmark/`

#### 故事线 3：从"重跑"到"复用"——实验系统省算力

实验跑一次就要消耗大量 token。之前改一个参数就得全部重跑。这一版让实验系统学会"省着花"：

1. **报告复用**：InPlaceReuseHandler（原地增补）+ CopyMigrateHandler（复制迁移），配置指纹识别判断是否实质相同
2. **缓存校验**：修复三层缓存配置不匹配问题，修改 config 后不再命中旧缓存
3. **429 退避**：call_with_retry 指数退避，压力测试确定安全并发上限（safe_max=21，默认 10）
4. **Resume 增强**：ResumeConfig 支持 YAML 配置，hash mismatch 修复

**关键文件**：`src/experiment_reuse.py`, `src/llm_retry.py`

#### 故事线 4：从"碎片"到"统一"——管线入口整合

之前 `--query`、`--interactive`、`--build-index` 各走各路，不指定 `--meal` 就报错。测试集生成、审核、合并散落在多个脚本。这一版做了统一：

1. **Meal 系统统一**：所有入口自动接入 Meal/Artifact 系统，`get_or_create_full_meal()` 自动创建默认全量 Meal
2. **测试集管线整合**：TestSetComposer（合并/过滤/增量组合）+ testset_review（AI 审核）+ testset_cli（统一 CLI 入口）
3. **多轮对话贯通**：chat_history 从 CLI → Pipeline → Generator 全链路贯通

**关键文件**：`src/testset_composer.py`, `src/testset_review/`, `src/testset_cli/`, `src/test_generation/distribution.py`

## 四、关键决策记录

| 决策 | 选择 | 理由 |
|------|------|------|
| 默认解析链路 | pymupdf4llm + pdfplumber(text), OCR off | 实验验证：OCR 耗时 -63.2%，text 策略表格质量最优 |
| 表格补强策略 | 多维度质量比较，默认优先补强 | 单维度判断过于简单，合并单元格是低质量明确信号 |
| Case 存储格式 | 5 文件落盘（manifest/config/meal/query/env） | 复用实验系统三层保障思路，单次查询场景精简版 |
| 实验复用模式 | in_place + copy_migrate 双模式 | in_place 适合迭代实验，copy_migrate 适合跨实验迁移 |
| API 并发上限 | safe_max=21, 默认 10 | 二分搜索压力测试实测，留足安全余量 |
| 测试分层 | unit / standard / all 三层 + xdist 并行 | 开发中秒级反馈，post-merge 分钟级验证 |
