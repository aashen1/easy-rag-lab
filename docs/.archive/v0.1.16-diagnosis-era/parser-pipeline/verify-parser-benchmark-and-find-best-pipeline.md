# 验收链路评测功能 & 初步判断最佳默认PDF解析链路

## 背景

`eval/parser_benchmark/` 模块实现了多管线PDF解析质量对比评估框架，当前已有：
- 6种管线组合配置（`parser_configs/baseline.yaml`）
- 1次成功运行记录（仅1个PDF：食品饮料行业ETF周报）
- 27个单元测试全部通过
- 210个PDF文件可用（113年报 + 97研报）

### 现有基准测试发现

| 管线 | 表格数 | 字符数 | 标题数 | 耗时 | 空单元格率 |
|------|--------|--------|--------|------|-----------|
| pymupdf4llm_pure | 3 | 27379 | 45 | 4.34s | 19.3% |
| pymupdf4llm_pdfplumber_lines | 3 | 27483 | 45 | 5.09s | 22.4% |
| pymupdf4llm_pdfplumber_text | 3 | 27483 | 45 | 4.86s | 22.4% |
| fitz_pure | 0 | 18400 | 6 | 0.11s | 0% |
| fitz_pdfplumber_lines | 0 | 18400 | 6 | 0.11s | 0% |
| fitz_pdfplumber_text | 0 | 18400 | 6 | 0.11s | 0% |

**关键问题**：fitz管线完全无法检测Markdown表格，且文本提取量少33%。

## 执行计划

### Step 1: 验收链路评测功能

**目标**：确认 `eval/parser_benchmark/` 模块实现无误

- [x] 运行单元测试 `pixi run test-unit -k "test_parser_benchmark"` → 27 passed
- [ ] 检查核心模块代码质量：runner.py、metrics.py、report_generator.py、test_cases.py
- [ ] 验证已有基准测试结果的合理性（1个PDF的6管线对比）
- [ ] 检查报告生成格式是否完整、指标是否正确

**验收标准**：代码逻辑正确、测试覆盖充分、报告输出格式合理

### Step 2: 创建抽样评测配置

**目标**：从210个PDF中抽取3-5%（约8-10个），覆盖年报和研报两类

抽样策略：
- 年报选取3-4个（不同公司、不同年份，优先选含大量表格的年报）
- 研报选取4-5个（不同行业，覆盖周报/月报/深度报告等不同格式）
- 总计约8个PDF

具体PDF选取（需验证文件存在后确定）：
- 年报：贵州茅台2023、工商银行2024、比亚迪2023、美的集团2024（年报通常含大量财务表格）
- 研报：白酒行业信用观察、光伏行业分析、半导体月报、银行理财月报、高温合金研报

创建配置文件 `parser_configs/sampled_eval.yaml`，复用6种管线组合。

### Step 3: 运行抽样评测

**目标**：使用抽样配置运行基准测试

```bash
pixi run parser-bench sampled_eval
```

预估耗时：8个PDF × 6管线 ≈ 8×5s(pymupdf4llm) + 8×0.2s(fitz) ≈ 42s

### Step 4: 分析结果并判断最佳默认链路

**目标**：基于评测数据，给出默认PDF解析链路推荐

分析维度：
1. **表格提取能力**：能否正确识别和提取表格（金融文档核心需求）
2. **文本完整性**：字符数/词数是否充分
3. **结构保真度**：标题层级是否保留
4. **表格质量**：空单元格比例、行列结构
5. **解析速度**：大规模处理时的效率

预期结论方向：
- pymupdf4llm 系列在表格和文本提取上显著优于 fitz
- pdfplumber 增强器的效果需在更多PDF上验证
- 需权衡速度与质量，给出推荐配置

### Step 5: 更新 config.yaml 默认配置（如需要）

根据分析结果，如当前默认配置（`pymupdf4llm`）不是最优，则更新 `config.yaml` 中的 `parser` 配置节。

## 风险与注意事项

1. **OCR 开启时 pymupdf4llm 耗时较长**：抽样评测中 OCR 已开启，年报类大文件可能耗时更久
2. **fitz 管线表格检测为0**：这是已知问题，fitz 不输出 Markdown 表格格式，但可能以纯文本形式保留了表格数据
3. **pdfplumber 增强器对 fitz 无效**：因为 fitz 不产生 Markdown 表格，pdfplumber 无替换目标
4. **抽样代表性**：8个PDF可能不足以覆盖所有文档类型，但作为初步判断足够
