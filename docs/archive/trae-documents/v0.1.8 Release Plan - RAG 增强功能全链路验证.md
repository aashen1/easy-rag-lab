## Phase 2: 实验套件运行（核心验证）

### 2.1 基线实验

**配置文件**: `exp_configs/baseline_v01x.yaml`
**目的**: 建立性能基准，作为后续对比的参照

**操作**:

```bash
pixi run exp baseline_v01x
```

**预期产出**:

* 实验报告（含检索指标 + 生成指标）

* 基线性能数据

### 2.2 检索方式对比实验

**配置文件**: `exp_configs/retrieval_comparison.yaml`
**目的**: 验证 BM25、向量、混合检索的效果差异

**变体**:

1. `vector_only` - 纯向量检索（基线）
2. `bm25_only` - 纯 BM25 稀疏检索
3. `hybrid_rrf` - 混合检索 RRF 融合
4. `hybrid_weighted_70_30` - 加权融合 0.7/0.3
5. `hybrid_weighted_50_50` - 加权融合 0.5/0.5

**操作**:

```bash
pixi run python eval/run_experiment.py --config exp_configs/retrieval_comparison.yaml
```

**验证要点**:

* 所有变体成功运行

* 混合检索效果优于单一检索（预期）

* 生成对应的实验报告

### 2.3 Reranker 对比实验

**配置文件**: `exp_configs/reranker_comparison.yaml`
**目的**: 验证 Cross-Encoder 重排的效果

**变体**:

1. `no_rerank` - 无重排（基线）
2. `rerank_top3` - 重排保留 top-3
3. `rerank_top5` - 重排保留 top-5
4. `hybrid_rerank` - 混合检索 + 重排

**操作**:

```bash
pixi run python eval/run_experiment.py --config exp_configs/reranker_comparison.yaml
```

**验证要点**:

* Reranker 正确加载并运行

* 重排后排序质量提升（MRR, NDCG）

* 生成对应的实验报告

### 2.4 查询改写对比实验

**配置文件**: `exp_configs/query_rewrite_comparison.yaml`
**目的**: 验证 HyDE 和 Multi-Query 改写策略效果

**变体**:

1. `no_rewrite` - 无改写（基线）
2. `hyde` - HyDE 假设性文档嵌入
3. `multi_query_3` - Multi-Query 3个子查询
4. `hyde_hybrid` - HyDE + 混合检索

**操作**:

```bash
pixi run python eval/run_experiment.py --config exp_configs/query_rewrite_comparison.yaml
```

**验证要点**:

* HyDE 和 Multi-Query 正确运行

* 改写策略提升检索效果

* 生成对应的实验报告

### 2.5 分块策略对比实验

**配置文件**: `exp_configs/chunking_strategy_comparison.yaml`
**目的**: 验证语义分块 vs 固定分块的效果

**变体**:

1. `fixed_512_overlap_0` - 固定分块（基线）
2. `semantic_threshold_50` - 语义分块 阈值0.5
3. `semantic_threshold_30` - 语义分块 阈值0.3
4. `semantic_percentile_25` - 语义分块 25百分位

**操作**:

```bash
pixi run python eval/run_experiment.py --config exp_configs/chunking_strategy_comparison.yaml
```

**验证要点**:

* 语义分块正确运行

* 对比不同分块策略的效果

* 生成对应的实验报告

## 风险与注意事项

### 时间成本

* 每个实验需要创建 meal + 生成问题集 + 运行评测

* 5个实验预计需要较长时间（取决于 PDF 数量和 LLM 响应速度）

* 建议：先用小规模采样（sample\_ratio: 0.05-0.1）快速验证

### 依赖检查

* 确认 BM25 相关依赖（rank\_bm25）已安装

* 确认 Reranker 相关依赖（transformers）已安装

* 如有缺失，需要先安装依赖

## 关键决策点

1. **实验采样比例**: 建议先用 0.1 快速验证，确认流程畅通后再向用户确认是否需要全量数据
2. **实验运行顺序**: 必须先运行基线实验，其他实验结果才有对比意义
3. **失败处理**: 如果某个实验失败，需要排查原因（依赖/配置/代码 bug），修复后重新运行
4. **结果记录**: 每个实验完成后立即记录关键发现，避免最后汇总时遗漏
