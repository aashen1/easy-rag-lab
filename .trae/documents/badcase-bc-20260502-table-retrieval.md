# Bad Case 排查计划：bc_20260502_073922_a0f321

## 问题概述

**问题**：香飘飘 的2026年3月13日 收盘价？

**预期答案**：13.04 元（来自《食品饮料行业ETF周报：茅台C端改革持续进行》第14页表6）

**实际结果**：系统回答"无法回答"，检索到的5个chunk全部来自无关文档（万科A、中国平安、隆基绿能、房地产行业周报），目标文档的chunk完全未被检索到。

---

## 根因分析

### 1. 解析层：复杂合并单元格表格结构被破坏

pymupdf4llm 将表6解析为 Markdown 表格，但存在严重的结构性问题：

- **多行合并单元格**：原始PDF中，多只股票的证券代码+简称被合并到同一个单元格，解析后用 `<br>` 连接
- **数据对应关系丢失**：第一列 `603711.SH<br>香飘飘<br>003000.SZ<br>劲仔食品` 与第二列 `13.04<br>53.8<br>10.65<br>48.0` 的对应关系需要按位置推断，嵌入模型无法理解
- **列头信息稀释**：列头 `收盘价<br>（0313）<br>总市值<br>（亿元）` 只在第一个chunk(p14_000)中出现，后续chunk完全丢失列名上下文

### 2. 分块层：固定分块硬切表格

- chunk_size=512, chunk_overlap=0, cross_page_overlap=0
- 表6被切成6个chunk（p14_000 ~ p14_005），"香飘飘"出现在 p14_003 和 p14_004
- p14_003：包含公司名但数据被截断
- p14_004：包含数据但缺少列头上下文
- **没有任何表格边界感知**，表格行被硬切

### 3. 检索层：纯向量搜索无法匹配表格内容

- `method: vector`（无BM25）
- 嵌入模型 bge-large-zh-v1.5 对 `<br>` 连接的混乱表格文本语义理解极差
- 查询 "香飘飘 的2026年3月13日 收盘价" 与 chunk 中的 `603711.SH<br>香飘飘<br>003000.SZ<br>劲仔食品` 语义距离很远
- **BM25 精确匹配 "香飘飘" 本可命中**，但未启用

### 4. 未启用的检索增强手段

| 手段 | 当前状态 | 影响 |
|------|----------|------|
| BM25 混合检索 | 关闭（method: vector） | 无法精确匹配关键词"香飘飘" |
| Reranker | 关闭 | 无法对低分但相关的chunk进行提权 |
| Query Rewrite | 关闭 | 无法扩展查询语义 |
| score_threshold | 0.3 | 被检索到的无关chunk分数0.45-0.49，说明阈值不是问题 |

---

## 改善方案

### 方案 A：短期快速见效（配置调整，无需改代码）

1. **启用混合检索**：`retrieval.method: hybrid`，BM25权重0.3
   - "香飘飘"作为精确关键词，BM25可以直接命中
   - 这是**最直接有效的改善**

2. **启用 Reranker**：`retrieval.reranker.enabled: true`
   - 对初始检索结果进行精排，提升相关chunk排名

3. **增大 top_k**：从5提升到10或15
   - 给 reranker 更多候选，提高召回率

4. **启用 Query Rewrite**：`retrieval.query_rewrite.enabled: true`
   - 扩展查询语义，如 "香飘飘" → "香飘飘 603711 收盘价 股价"

### 方案 B：中期结构优化（需要代码改动）

5. **表格感知分块**：在 chunker 中检测 Markdown 表格边界，确保表格不被硬切
   - 检测 `|---|` 分隔行和 `|...|` 数据行
   - 将完整表格作为一个chunk，若超长则按行组切分并重复列头
   - 预计改动：`src/chunker.py` 新增 `table_aware` 分块逻辑

6. **表格行展开**：在解析后处理阶段，将合并单元格的 Markdown 表格展开为逐行格式
   - 输入：`|603711.SH<br>香飘飘<br>003000.SZ<br>劲仔食品|13.04<br>53.8<br>10.65<br>48.0|`
   - 输出：
     ```
     | 证券代码 | 证券简称 | 收盘价(0313) | 总市值(亿元) |
     | 603711.SH | 香飘飘 | 13.04 | 53.8 |
     | 003000.SZ | 劲仔食品 | 10.65 | 48.0 |
     ```
   - 预计改动：`src/parsers/pymupdf4llm_parser.py` 新增 `expand_merged_table_cells()` 后处理

7. **表格摘要增强**：为包含表格的chunk自动生成自然语言摘要并拼接到chunk文本中
   - 例如："[表格摘要：本表包含食品饮料板块重点公司盈利预测，香飘飘收盘价13.04元，总市值53.8亿元...]"
   - 提升嵌入模型对表格内容的语义理解

### 方案 C：长期架构升级

8. **结构化表格存储**：将表格解析为 JSON/CSV 结构化数据，独立于文本chunk存储和检索
   - 表格查询走结构化检索路径，文本查询走向量检索路径
   - 需要较大的架构改动

9. **多模态解析**：使用 GPT-4V / Qwen-VL 等视觉模型直接理解PDF表格图像
   - 绕过 pymupdf4llm 的表格解析限制
   - 成本较高但效果最好
