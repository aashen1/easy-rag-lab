# CLAUDE.md 长度优化分析与计划

## 问题

IDE 提示 CLAUDE.md 超过 1000 字符，建议缩短。这个建议是否有道理？是否值得遵守？

## 当前状态

| 指标      | 数值        |
| ------- | --------- |
| 字符数     | 4,144     |
| 行数      | 116       |
| 指令数（估算） | \~40-50 条 |

## 行业最佳实践汇总

### 1. context-doctor（CLAUDE.md 专用 lint 工具）的规则

| 规则    | 级别      | 阈值                                                   |
| ----- | ------- | ---------------------------------------------------- |
| CD001 | error   | >300 行                                               |
| CD002 | warning | >100 行，理想 \~60 行                                     |
| CD003 | error   | >100 条指令（LLM 可靠遵循上限 150-200 条，Claude Code 自带 \~50 条） |
| CD004 | warning | >50 条指令                                              |

### 2. DataCamp 官方指南

> "Claude Code's system prompt already consumes around 50 instructions, and LLMs reliably follow roughly 150-200 total instructions before degradation sets in. Some experienced teams run with fewer than 60 lines."

### 3. TurboDocx 最佳实践

> "The absolute ceiling is roughly 300 lines before Claude starts losing signal in the noise."

> "A good test for every line: would removing it cause Claude to make mistakes? If not, cut it."

### 4. Claude Code 官方建议

官方建议控制在 **200 行以内**，超过此长度会消耗更多上下文，且规则更容易被忽略。

### 5. 实际项目案例

* autonomous-dev 项目：41,836 字符（767 行）→ 目标 <35,000 字符

* 其建议：复杂项目 20,000-30,000 字符

## 核心结论

### 1000 字符限制——不合理，不必遵守

**理由：**

1. **无行业依据**：没有任何权威来源推荐 1000 字符作为阈值。行业共识是按**行数**和**指令数**衡量，而非字符数
2. **过于严苛**：1000 字符约等于 15-20 行，连项目简介 + 核心规范都写不下
3. **混淆了指标**：关键不是"多短"，而是"指令是否被有效遵循"

### 当前 4144 字符 / 116 行——合理但有优化空间

| 评估维度          | 当前状态                                               | 判定      |
| ------------- | -------------------------------------------------- | ------- |
| 行数 (116)      | 略超 CD002 warning 阈值 (100)，远低于 CD001 error 阈值 (300) | ⚠️ 轻微超标 |
| 指令数 (\~40-50) | 低于 CD004 warning 阈值 (50)，远低于 CD003 error 阈值 (100)  | ✅ 健康    |
| 字符数 (4144)    | 远低于复杂项目上限 (20K-30K)                                | ✅ 健康    |

### 真正值得关注的不是"缩短"，而是"精炼"

核心原则来自 DataCamp：

> **"Would removing it cause Claude to make mistakes? If not, cut it."**

## 优化建议

### 不建议做的事

* ❌ 为凑 1000 字符而大幅删减——会丢失关键上下文

* ❌ 把所有规则都外移到其他文件——CLAUDE.md 是每次 session 必读的，关键规则必须在此

### 建议做的事：渐进式精炼（Progressive Disclosure）

目标：从 116 行 → \~80 行，指令数不变，信息不丢失

#### 策略 1：外移详细说明，保留核心规则

当前 CLAUDE.md 中有几处"教程式"内容，可以改为"规则 + 链接"：

| 内容           | 当前形式                  | 优化后                 |
| ------------ | --------------------- | ------------------- |
| Issue 系统命令列表 | 完整列出 6 个命令 + 类型 + 状态流 | 保留核心命令，详细说明链接到 docs |
| 收件箱检查规则      | 完整流程描述                | 保留核心规则，流程细节链接到 docs |
| TODO 归档检查规则  | 完整流程描述                | 保留核心规则，流程细节链接到 docs |
| 版本叙事表        | 6 行表格                 | 可压缩为 1 行概述 + 链接     |

#### 策略 2：合并重复/冗余表述

* "禁止 `git add -A` / `git add .`" 在版本控制和 commit-rule.md 中重复

* 文件删除规则在 CLAUDE.md 和 trashbin-rule.md 中重复

* 可以在 CLAUDE.md 中只保留一句话核心规则 + 链接

#### 策略 3：删除 Claude 已知的通用知识

* "禁止使用 print" → ruff 规则已覆盖

* "所有公共函数必须标注参数类型" → 这是 Python 社区常识

## 实施计划

### Step 1：分析每条指令的必要性

对 CLAUDE.md 中每条规则做"删除测试"：去掉这条，Claude 会出错吗？

### Step 2：重构为"核心规则 + 渐进式引用"

* CLAUDE.md 保留 \~60-80 行核心规则

* 详细流程、命令参考等外移到 `docs/dev-guides/` 下

* 使用链接引用：`详见 docs/dev-guides/issue-system.md`

### Step 3：验证优化效果

* 确认所有关键规则仍在 CLAUDE.md 中（AI 每次必读）

* 确认外移内容有明确链接（AI 按需读取）

* 运行 context-doctor 或手动检查指令数 < 50

## 最终回答

| 问题             | 回答                                              |
| -------------- | ----------------------------------------------- |
| 1000 字符限制有道理吗？ | **没有**。无行业依据，过于严苛，1000 字符连基本项目上下文都容纳不下          |
| 值得遵守吗？         | **不值得**。但"精炼"本身是值得追求的目标                         |
| 当前文件需要优化吗？     | **轻度优化即可**。116 行略超理想值，但远未到危险区。可通过渐进式精炼降到 \~80 行 |
| 优化的正确方向？       | 不是"缩短字符数"，而是**减少指令冗余 + 渐进式引用**                  |
