## 三、需求合理性评估

### 3.1 设计稿中的不合理或不清晰需求点

#### 问题 1: 轻量/全量双模式定义不清晰

**设计稿位置**：§1.2 C6，§9 Phase 2 Task 2.5

**问题描述**：
- 设计稿提到"轻量模式处理 1-2 个 PDF，全量模式同现有实验系统"，但未明确定义：
  1. "轻量"和"全量"的具体行为差异是什么？
  2. 全量模式下，Agent 是否应该自动调用 Meal 批量体系？
  3. 全量模式下，删除阈值、操作指导是否应该不同？

**影响**：实现时缺乏明确指导，导致该功能未完成

**建议**：
1. 明确轻量模式：默认模式，处理单个 PDF，严格删除限制，单步操作指导
2. 明确全量模式：显式启用（`--full` 或 UI 切换），可处理多个 PDF，宽松删除阈值，批量操作指导
3. 在 prompt 中注入模式相关指导

---

#### 问题 2: 经验持久化方案未明确

**设计稿位置**：§1.2 C9，§4.2.4 Memory Store

**问题描述**：
- 设计稿提到"跨 session 积累经验"，但未明确：
  1. 经验应该持久化到哪里？（SQLite？JSON 文件？）
  2. 经验的 namespace 设计是什么？（按用户？按 PDF 类型？）
  3. 经验的检索方式是什么？（语义搜索？关键词匹配？）

**影响**：实现时使用 InMemoryStore，进程重启后经验丢失

**建议**：
1. 采用 JSON 文件持久化（`data/agent_experience.json`）
2. namespace 设计：`(user_id, "maintenance_experience", pdf_type)`
3. 检索方式：当前使用 `get_all_experiences`，未来可支持语义搜索

---

#### 问题 3: 白名单机制定义不完整

**设计稿位置**：§1.2 C12，§7.1 风险矩阵

**问题描述**：
- 设计稿提到"白名单机制限制危险操作"，但未明确：
  1. 白名单是"硬拦截"还是"软拦截"？
  2. 如何防止 LLM 通过组合合法工具绕过白名单？
  3. delete_source 累计删除的限制是什么？

**影响**：实现时采用"软拦截"，存在绕过风险

**建议**：
1. 明确白名单为"硬拦截"：直接拒绝，不触发 interrupt
2. 增加 delete_count 计数器，累计删除达到阈值时硬拦截
3. 在 prompt 中明确告知 LLM 禁止绕过白名单

---

#### 问题 4: Phase C 迁移优先级不明确

**设计稿位置**：§4.5 共享单元与现有模块的迁移路径

**问题描述**：
- 设计稿提到"Phase C：实验系统迁移到共享单元"，但未明确：
  1. Phase C 是否是 Phase 3 的必须项？
  2. 迁移的优先级是什么？
  3. 迁移的风险评估是什么？

**影响**：Phase C 未实现，实验系统和 Agent 存在两套并行代码

**建议**：
