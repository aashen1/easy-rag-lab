# RAG 评测系统修复规格说明书

## 1. 修复目标

修复 RAG 评测系统中导致实验结果不可信、无法完全复现的严重问题，确保实验资产包完整性和数据可信度。

| 任务 ID | 任务名称 | 严重程度 | 描述 |
|---------|----------|----------|------|
| T1.1 | 问题集快照保存修复 | P0 | 修复问题集生成后未正确保存的问题，确保 test_sets/{name}.json 包含完整元数据 |
| T1.2 | Manifest 修复 | P0 | 修复 manifest.json 中 test_sets 字段记录为 null 的问题 |

## 3. 详细规格

### 3.1 T1.1: 问题集快照保存修复

**问题描述**：
- `test_sets/None.json` 中所有字段为 null
- 实际生成的问题未保存到快照

**修复方案**：
- 在问题集生成后，将完整的问题内容写入 `test_sets/{test_set_name}.json`
- 包含字段：name, strategy, num_questions, created_at, meal_data_id, questions (数组)
- questions 数组中每个问题包含：id, question, answer, expected_sources, expected_chunks, category, difficulty, question_type

**验收标准**：
- 运行实验后，`test_sets/` 目录下应有正确命名的 JSON 文件
- JSON 中包含所有生成的问题及完整元数据
- manifest.json 中的 test_sets 字段正确引用问题集名称

### 3.2 T1.2: Manifest 修复

**问题描述**：
- manifest.json 中 test_sets 记录为 `[null]`

**修复方案**：
- 在实验初始化时正确记录 test_sets 信息
- 确保使用实际的问题集名称而非 null

**验收标准**：
- manifest.json 中 test_sets 字段为非 null 的数组

### 3.3 T1.3: 实验日志归档

**问题描述**：
- 无实验过程日志，无法追溯执行细节

**修复方案**：
- 在实验运行目录下创建 `experiment.log` 文件
- 记录实验各阶段的起止时间
- 记录关键事件和错误信息

**验收标准**：
- 实验目录中存在 `experiment.log` 文件
- 日志包含时间戳和关键事件描述

### 3.4 T1.4: test_set 字段修复

**问题描述**：
- results/baseline.json 中每个问题的 test_set 字段都是 "unknown"

**修复方案**：
- 在保存结果时正确填充 test_set 字段
- 使用实际的问题集名称

**验收标准**：
- 结果文件中每个问题的 test_set 字段为有效名称

### 3.5 T2.1: FPR 指标修正

**问题描述**：
- FPR = 1.0 被错误解读为"无误检"
- 实际 FPR=1 表示 100% 误报率

**修复方案**：
- 审查 FPR 的计算逻辑
- 修正文档中的解释说明
- 确认当前场景下 FPR 的正确计算方式

**验收标准**：
- FPR 计算逻辑正确
- 文档说明准确

### 3.6 T2.2: Hit Rate 异常检测

**问题描述**：
- Hit Rate = 1.0 过于完美，不符合实际

**修复方案**：
- 添加 Hit Rate 阈值告警（如 > 0.95 时发出警告）
- 在实验报告中标记异常值

**验收标准**：
- 当 Hit Rate 异常高时，实验报告中有明确告警

### 3.7 T2.3: expected_chunks 严格化

**问题描述**：
- 单个问题标记了 14+ 个 expected_chunks
- 覆盖近 1/3 文档，等于没有做真正的 chunk 级评估

**修复方案**：
- 问题生成时限制 expected_chunks 数量（建议 1-3 个）
- 或者改用"锚点 chunk"策略
- 修改问题生成阶段的 prompt 和后处理逻辑

**验收标准**：
- 每个问题的 expected_chunks 数量不超过 3 个

### 3.8 T2.4: Ground Truth 质量审计

**问题描述**：
- 问题可能泄露答案信息

**修复方案**：
- 添加问题-答案相关性检查
- 在问题生成后进行质量验证

**验收标准**：
- 问题质量检查机制已实现

### 3.9 T3.1: 环境版本快照

**问题描述**：
- 无环境版本信息

**修复方案**：
- 使用 `pip freeze` 或记录关键依赖版本
- 记录嵌入模型、LLM 版本信息

**验收标准**：
- 实验报告中包含环境版本信息

## 4. 修复优先级

1. **立即修复 (P0)**: T1.1, T1.2
2. **高优先级 (P1)**: T1.3, T1.4, T2.1, T2.2
3. **中优先级 (P2)**: T2.3, T2.4, T3.1
